## 1. 产品定位（一句话）

> 宠物常驻右下角，把「当前有哪些对话在跑、哪些失败了」用一句话 + 一个毛玻璃浮层如实告诉用户；**失败就是失败**（绝不伪装绿色成功），平时不打扰。

## 2. 交互规范（已评审确认）

| 交互 | 规则 |
|---|---|
| 点宠物 | **toggle** 展开/收起概览面板 |
| 点面板外部 | **关闭**（pointerdown 在浮层外 → 关） |
| ESC | **关闭**（键盘可达性） |
| 右上角关闭按钮 | **不需要**（瞬态浮层范式，去掉） |
| 面板打开时 | 宠物显示**激活态**（淡底反馈，知道从哪开的） |
| 气泡（提示） | 独立于面板：状态变化时出现，**3.5s 后消失**；与面板互不干扰 |
| 焦点 | 面板关闭后焦点归还触发元素（无障碍） |

**设计语言**：这是「瞬态浮层（popover）」，不是常驻面板——"看一眼"的信息，随点随消，符合轻打扰原则。

## 3. 视觉规范（DSH 令牌 + 毛玻璃，原型 v0.2 已实现）

- **令牌铁律**：颜色只用 `--dsw-alias-*`（随 `body[data-ds-dark-theme]` 深浅自适应）；原型 `:root` 有独立演示兜底值；
- **毛玻璃配方**（宠物气泡同款，面板弱化不明显）：
  - 浅色：`background:rgba(255,255,255,.45)` + `backdrop-filter:blur(14px) saturate(1.5)` + `border:1px solid rgba(255,255,255,.55)` + `border-radius:16px`；
  - 深色：`background:rgba(28,30,36,.45)` + `border:rgba(255,255,255,.14)`；
- **状态色**：运行中 `state-business-primary`（蓝）· 失败 `state-error-primary`（红）· 完成 `state-success-primary`（绿）· 待机 `label-tertiary`（灰）；
- **面板规格**：宽 320px、标题 14px/500、统计大数字 20px/600、行悬停 `interactive-bg-hover`、软阴影（弱化层级）；
- 状态文案：运行中 / 失败 / 已完成 / 待机（如实，不模糊）。

## 4. 状态与数据

- 会话状态：**运行中 / 失败 / 已完成 / 待机**——**失败是真实失败**（绝不显示绿色成功）；
- 宠物情绪映射（优先级 失败 > 运行中 > 完成 > 空闲）：着急 😵💫 / 忙碌 🐋 / 开心 🐳 / 打盹 💤；
- 气泡文案：`「N 个对话失败 · M 个进行中」` / `「M 个对话进行中」` / `「全部完成」`；
- 数据来源：**读平台已有投影**（`useSessions` 的 running/completed 等），不自己建状态机、不做 stuck 检测。

### ✅ M0 技术验证结论（2026-08-22 已实证并回填）
| # | 验证项 | 结论（实证） |
|---|---|---|
| T1 | `useSessions` 语义 / **"失败"如何判定** | **客户端可注入 `ctx.get("sessions")`**（SessionRuntime 经 `rootCtx.reflect.provide("sessions", this)` 注册，非 React 专属）。`.list` snapshot store 的 byId 项含 `running` / `completed` / `blank` / `updatedAt` / `displayTitle`。**失败 = `sessions.get(id).snapshot().lastAgentError` 非空**：host 的 `agent/error` 事件 → `host/agent-error` 帧 → `handleAgentError` 写入（每轮新 prompt 会重置，即"最近一次交互失败"）。**优先级：失败 > 运行中 > 已完成 > 待机**，失败绝不伪装成功 |
| T2 | 状态变化如何事件驱动订阅 | **零轮询**。双通道订阅：`list.subscribe()`（新增/移除/运行状态变化，snapshot store 原生）+ `session.subscribe()`（per-session notifier，`lastAgentError` 变化触发 markDirty）。host 的 `session/status` / `agent-error` / `session-added` / `session-removed` 帧驱动，面板打开才订阅、关闭即退订 |
| T3 | stats 端点复用 | **零新端点**。状态概览纯客户端订阅平台投影，不复用 `/personal-center/stats`（那是 30s 轮询的 token 统计，口径不同）。host 端零改动 |

**结论**：规格的"读平台已有投影、事件驱动、零新依赖"全部成立，且比预期更轻——无需任何 host 端改动，全部实现落在 `lib/client.js` 的纯 DOM 层。

## 5. 轻量约束（硬性验收，不是建议）

1. **空闲零开销**：无对话状态变化时，不轮询、无定时器、无后台任务；
2. **事件驱动**：状态变化走订阅（useSessions 已有更新流），不自己起轮询；
3. **面板懒挂载**：面板点击才创建 DOM，关闭即销毁；气泡 3.5s 自动消失；
4. **零新依赖**：不引图表库/不建索引/不重复拉取；数据全部复用现有投影；
5. 实测口径：开/关概览前后内存增量 < 5MB、空闲 CPU ≈ 0%（DevTools 对比）。
