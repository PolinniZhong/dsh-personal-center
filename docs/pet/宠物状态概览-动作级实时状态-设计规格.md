## 1. 产品定位（一句话）

> 宠物状态概览从「告诉你几个在跑」升级为「告诉你**正在干什么**」：会话运行中实时显示「正在读取 xxx / 正在执行命令 …」，完成即「就绪 ✓」——像 Codex 宠物一样，把真实动作实时呈现，不假装、不滞后。

## 2. 用户目标（对齐 Codex 截图）

| 场景 | Codex 表现 | 本迭代目标 |
|---|---|---|
| 会话运行中 | 「UI 原型设计 (2) 正在读取 new-work.md」 | 面板显示「正在读取 new-work.md」（动作级文案，实时刷新） |
| 会话完成 | 「UI 原型设计 (2) 就绪」+ 绿勾 | 面板显示「已完成/就绪」+ 绿色反馈 |

## 3. 数据契约（已基于 DSH 源码实证 ✅）

| 能力 | 结论 | 依据（dsh-client-runtime） |
|---|---|---|
| 运行中 | ✅ 已用 | `sessions.list.getSnapshot().byId[id].running` |
| 动作（正在读取 xxx） | ✅ **可提取** | `sessions.manager.get(id).getSnapshot().nodes` 中**最后一个 `kind:"tool-call"` 节点**：`.name`（工具名）+ `.argsRaw`（参数字符串） |
| 完成/就绪 | ✅ 已用 | `byId[id].completed` / `running:false` |
| 实时性 | ✅ **零改动** | host `session/event` 帧（含 tool 事件）→ wrapper `notifier.markDirty()` → 已订阅的 `session.subscribe()` 自动重渲染 |
| 工具名/参数 | ✅ 已确认 | `read`→`file_path`；`write`/`edit`→`file_path`；`bash`→`command`；其余工具名见工具注册表 |

**关键结论**：Codex 两类状态在 DSH 里数据全都有、实时链路已通。实现只把「运行中」细化为动作文案，**零 host 改动、零新端点、零轮询**。

### 3.1 节点结构参考

```
nodes（legacy 会话消息节点）
└─ 最后一个 kind:"tool-call" 节点
   ├─ name: "read"                       // 工具名（read/write/edit/bash/...）
   ├─ callId: "call_xxx"
   └─ argsRaw: '{"file_path":"new-work.md"}'   // 参数 JSON 字符串
```

- `read` / `write` / `edit` → 参数 `file_path`（已确认必填）→ 「正在读取/写入/编辑 <文件名末段>」
- `bash` → 参数 `command` → 「正在执行命令 <前 24 字符>…」
- `web_search` 等 → 「正在搜索」
- 未知工具 → 「正在调用 <name>」
- **无 tool-call 节点**（正在思考/流式输出）→ 回落「运行中」

## 4. 功能规格

### 4.1 动作文案提取（核心新增）
- `_project()` 中，对 **running 会话**取 `s.getSnapshot().nodes`，提取最后一个 `kind:"tool-call"` 节点 → 生成动作文案；
- 状态优先级**不变**：失败 > 运行中（带动作文案）> 已完成 > 待机；
- 动作文案展示在会话行内（状态徽标前/后），不新增视觉组件。

### 4.2 完成态增强（对齐第二张截图）
- `completed` 会话 → 「已完成」绿徽标（沿用现有 `state-success-primary`），必要时列表行加对勾；
- （可选）状态变化瞬间气泡弹「全部完成」——**本期默认不做**，避免回到"两个气泡"老问题，仅面板内表达。

### 4.3 实时性
- **零新增订阅**：沿用现有 `list.subscribe()` + `manager.get(id).subscribe()`；
- 动作变化（read → bash → done）由 host 事件自动驱动重渲染。

## 6. 验收清单

- [ ] 会话运行中 → 面板实时显示「正在读取 <文件>」/「正在执行命令 …」；
- [ ] 动作变化（如 read → bash）面板自动更新，无需手动刷新；
- [ ] 会话完成 → 显示「已完成/就绪」绿色反馈；
- [ ] 多会话并行 → 每个 running 会话各有动作文案；
- [ ] 失败状态仍红色如实（优先级最高，动作文案不覆盖）；
- [ ] 无 tool-call 节点（思考中）→ 回落「运行中」不崩；
- [ ] 轻量约束不破坏：面板关闭零订阅零定时器、懒挂载、零新依赖；
- [ ] 回归：既有 smoke 23 项全绿 + 新增动作文案断言。

## 7. 对抗检查（防"改了没改对"）

1. smoke fake 升级：session 的 `getSnapshot()` 增加 `nodes`（含 tool-call 节点），断言动作文案正确提取（read→文件、bash→命令、无节点→回落、失败→红色优先）；
2. grep 验证：无 `sessions.get` 残留、无旧文案遗留、i18n key 与代码引用一致；
3. 真实环境验证点：用探针确认 `nodes` 实际结构后再定稿文案映射（避免假设与运行时不符）。
