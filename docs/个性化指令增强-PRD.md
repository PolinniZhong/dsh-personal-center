## 1. 产品概述

### 1.1 一句话定位
把「个性化」从**一条全局指令**升级为**分层指令体系**：全局（身份基线）+ 按工作区（项目适配）+ 模板库（一键复用）——不同项目自动带不同人设，配置一次、处处生效。

### 1.2 背景
- 现有「个性化」只有一条全局自定义指令（order 10 注入），所有会话同一人设；
- 用户多工作区/多项目是常态（如 03_日常对话 / Omi-DSH / 0820），不同项目需要不同角色与工作原则，现状只能手动改全局指令、或每会话口头说明；
- 好的人设无法沉淀复用（换项目要重写）。

### 1.3 价值主张
| 价值 | 说明 |
|---|---|
| 项目适配 | 每个工作区自动带对应人设（AI 一进项目就知道怎么干活） |
| 零负担 | 模板一键套用，无需维护复杂规则 |
| 复用沉淀 | 好的人设存为模板，新项目一键启用 |
| 增强核心 | 强化「个性化」这一核心模块（非边角料），提升个人工作台粘性 |

## 2. 第一性原理评审（设计依据）

**底层需求**：身份一致性 / 项目适配 / 零负担 / 可复用。

**推导原则**：
1. **分层注入**：全局 = 身份基线；工作区 = 项目适配；模板 = 复用；
2. **叠加不冲突**：工作区指令追加在全局之后（同一 custom-instructions 段，按会话 cwd 选择）；
3. **配置零负担**：模板一键套用；默认全局生效，工作区为可选增强；
4. **静默高效**：仅在提示词组装时注入一次，不增加每轮开销。

## 3. 目标与非目标

### 3.1 目标
- G1：不同工作区自动注入对应指令（按会话 cwd 匹配）（P0）；
- G2：内置 + 自定义指令模板，一键应用到全局或指定工作区（P0）；
- G3：合并后指令**预览**（所见即所得）（P0）；
- G4：会话头部轻量提示当前指令来源（P1）；
- G5：纯本地、零网络、注入性能不劣化（P0，贯穿）。

### 3.2 非目标
- 不做按模型/预设的条件注入（P2 可选）；
- 不做指令的 A/B 测试/统计；
- 不改变 DSH 内置 persona/preset（分工不越界）。

## 6. 功能需求

### 6.1 分层指令（FR-CI-1~2，P0）

**FR-CI-1 全局指令（保留）**
- 现有行为不变：一条全局文本，order 10 注入所有会话。

**FR-CI-2 按工作区指令**
- 数据结构：`{ workspacePattern → text }`（工作区按会话 cwd 前缀匹配，支持通配/精确路径）；
- 注入规则：有匹配工作区 → 全局 + 工作区指令（追加）；无匹配 → 仅全局（行为与现状一致）；
- 多工作区匹配：取最长前缀匹配（最具体优先）；无匹配回退全局（不报错）；
- 存储：`settings.yaml`（自有命名空间，扩展 `personal-center-instructions`），纯本地。

**实现定稿（v0.7.0，2026-08-22）**：
- 命名空间 `personal-center-instructions` = JSON 字符串 `{ "workspaces": { "<cwd前缀>": "<文本>" }, "templates": [...] }`（同 `personal-center-pricing` 先例：schema 只校验字符串、解析容错、坏 JSON 回退空配置）；
- **匹配算法**：`cwd.startsWith(key)` 收集全部命中 → 取 key 最长者（最具体优先）；无命中 → 全局；
- **合并格式**：`全局 + "\n\n" + 工作区文本`（同一 custom-instructions 段内追加）；
- **provider 契约**：`variable("customInstructions", (context) => …)` 读 `context.agent.session.header.cwd`；无 cwd / 无配置 → 返回全局（与 v0.5.1 一致）；全局也空 → 返回 `""`（绝不返回 undefined）；
- 全局文本继续留在现有 `custom-instructions` 命名空间（**不迁移、不丢配置**）。

### 6.2 指令模板库（FR-CI-3，P0）

**FR-CI-3 模板库**
- 内置模板 3~5 个：产品经理 / 开发者 / 写作 / 翻译 / 通用助手（高质量、可直接用）；
- 自定义模板：从现有指令「存为模板」、或新建；
- 「应用」：一键写入全局 或 指定工作区（应用后可在该处编辑）；
- 模板管理：编辑/删除/（可选）导入导出。

**实现定稿（v0.7.0）**：
- 内置模板固定 5 个：产品经理 / 开发者 / 写作 / 翻译 / 通用助手（默认合并返回，用户可基于其「存为模板」自定义）；
- 模板对象：`{ id, name, desc, text }`，自定义模板持久化在 `personal-center-instructions.templates`；
- 「应用」交互（对齐 Demo）：每张模板卡片两个按钮「应用到全局」（写入 `custom-instructions.text`）与「应用到当前工作区」（写入对应 cwd 前缀 key；目标工作区不存在则自动以当前 cwd 前缀新建）；

### 6.3 注入预览（FR-CI-4，P0）

**FR-CI-4 合并预览**
- 个性化 tab 底部实时显示「全局 + 当前工作区」合并后的最终指令文本；
- 切换工作区时预览联动更新；明确标注"将注入到所有该工作区会话"。

### 6.4 来源提示（FR-CI-5，P1）

**FR-CI-5 会话头部来源提示**
- 会话头部/输入区轻量徽标：「指令:全局」或「指令:工作区X」；悬停显示来源明细；
- 不打扰：正常情况低调，点击可跳转到个性化 tab。

### 6.5 设置 UI（FR-CI-6，P0）

**FR-CI-6 个性化 tab 重构**
- 布局：三个子区（全局 / 按工作区 / 模板库）+ 底部注入预览；
- 工作区列表：自动发现 + 手动添加（路径）；当前会话工作区高亮；
- 全部遵循 DESIGN-SYSTEM（令牌/间距/圆角）与现有「个人」分区风格。

## 7. 对抗性审查（已修正，结论并入需求）

| 攻击 | 修正（已并入上面 FR） |
|---|---|
| ① per-workspace 太复杂 | 模板一键套用 + 默认全局生效（US-5）；工作区配置为展开可选层 |
| ② 叠加混乱 | FR-CI-4 合并预览，所见即所得 |
| ③ token 成本 | 组装时一次注入，与现有机制相同；工作区追加不倍增 |
| ④ 工作区识别 | cwd 前缀最长匹配 + 无匹配回退全局（FR-CI-2） |
| ⑤ 模板变摆设 | 内置高质量模板 + 一键应用（FR-CI-3） |
| ⑥ 不知道当前生效哪套 | FR-CI-5 来源提示 |
| ⑦ 与 persona/preset 冲突 | 注入段 order 10 与 persona(order 0) 分工，文档写明边界 |

## 8. 交互与视觉（DSH 设计规范）

- 全部使用 `--dsw-alias-*` 令牌（深浅自适应）；间距/字号/圆角遵循 DESIGN-SYSTEM；
- 个性化 tab 三个子区用「胶囊子 tab」（与现有「插件」分区 tab 风格一致：20px 高、`interactive-bg-hover` 全圆角）；
- 模板卡片：12px 圆角、标题 14px/500、描述 12px、悬停 `interactive-bg-hover`、「应用」按钮 `button-primary-fill` + `label-primary-foreground`；
- 注入预览：弱化容器（`bg-layer-3` + 12px 圆角）、等宽字体展示文本、来源标注；
- 工作区当前项高亮 `state-business-primary`；
- 空态：无工作区指令时显示「未配置，使用全局指令」（不报错）。

## 9. 非功能需求

- **注入性能**：组装时按 cwd 查一次映射（内存缓存），不增加每轮开销；文本量级 K 级，可忽略；
- **隐私**：纯本地（settings.yaml），零网络；与现有 custom-instructions 口径一致；
- **兼容**：无工作区匹配时行为与现状完全一致（向后兼容）；
- **轻量**：无新依赖、无轮询（与状态概览同为"读配置+注入"的轻量模式）。

## 14. 技术可行性验证（源码确认）与行业参考

### 14.1 技术可行性：per-workspace 注入 ✅ 零新接口

- 平台 seam（已源码确认 `dsh-agent-loop/lib/index.js:1026`）：官方内置 `ctx.systemPrompt.variable("cwd", (context) => context.agent?.session.header.cwd)`——**变量 provider 每次组装收到 `context`，可读 `context.agent.session.header.cwd`**；
- 我们的注入机制（`systemPrompt.section` + `variable("customInstructions")`）**直接可用**：把 provider 从"读全局文本"改为"按 cwd 匹配工作区 → 返回合并文本"即可；
- 无需改核心、无新接口、无新依赖——**每次会话组装时自动按工作区求值**（与官方 `{{cwd}}` 同 seam）。

### 14.2 行业参考（Codex 等平台的标准模式）

| 平台 | 机制 | 对应我们 |
|---|---|---|
| Codex (OpenAI) | AGENTS.md 分层（`~/.codex` → 项目根 → 子目录，按工作目录自动加载） | 全局 + 按工作区 |
| Claude Code | CLAUDE.md 分层（同 Codex） | 全局 + 按工作区 |
| Cursor | Rules + `.cursor/rules/*.mdc`（**glob 条件触发**） | 全局 + 工作区 + 条件引擎（v0.7） |
| ChatGPT 桌面端 | 全局自定义指令 + 项目说明 | 全局 + 工作区 |

> 结论：本产品做的是行业标准模式；**差异化 = 注入预览（所见即所得）+ 模板一键应用 + 个人工作台生态联动 + 设计质量**（行业工具均无"合并效果预览"UX）。

> ✅ **已确认（2026-08-22）**：采用行业标准「全局 + 项目级自动适配」分层模式（参考 Codex AGENTS.md / CLAUDE.md / Cursor Rules / ChatGPT 项目说明）；本产品按 **DSH 工作区（cwd 匹配）** 实现项目级，附加差异化（预览/模板/生态/设计质量）。

### 14.3 业务流运行时验证（源码级，2026-08-22）

**业务流**：配置（settings.yaml）→ 每轮组装 → provider 读 cwd → 匹配工作区 → 返回合并文本 → 渲染注入。

| 步骤 | 接口 | 验证结果（源码位置） |
|---|---|---|
| ① 配置存储 | 自定义 settings 命名空间 | ✅ 现有功能在跑（pricing/pet 同款：`settings.register` + settings.yaml 持久化） |
| ② 每轮触发组装 | `systemPrompt.assemble(assembleContextFor(this, signal))` | ✅ `dsh-agent-loop/lib/index.js:497`——每 turn 组装一次 |
| ③ provider 收到 context | `variable(name, provider)` → `provider(context)` | ✅ `dsh-system-prompt/lib/index.js:245-246`；`assembleContextFor` 传入 agent（类型声明 `agent?: Agent`） |
