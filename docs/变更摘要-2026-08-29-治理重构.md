## 一、背景：为什么要治理

`dsh-personal-center` 已扩展到 **4 个模块**（Token 用量 / 个性化 / 外观 / 宠物），全部堆在一个 3372 行的 `lib/client.js` 里，且**多个模块共用泛化类名 `.dsh-pc-ss-*`**。

**直接后果**：AI 在另一个会话改「外观字号」时，**一会改宠物模块、一会改外观模块**——因为：
1. 类名不区分模块（`.dsh-pc-ss-*` 被外观和宠物·会话状态共用）；
2. 没有文档钉边界（AGENTS.md 还是旧的 3 模块、旧名「个人资料」）；
3. 单文件 3000+ 行，AI 定位靠 grep，grep 出来的类名跨模块。

### A. 会话概览面板（PetStatusPanel）迭代（8 项）

1. **标题**「会话状态概览」→「会话概览」（i18n `petStatusTitle`，zh）。
2. **摘要计数**：进行中/失败/完成**数值为 0 的项整项隐藏**（`sumEls` 从指向 `<b>` 改为指向父 span，`display:none` 切换）；数字字号 **14px → 11px**（与标签一致）。
3. **面板宽度** 320 → **256px**（CSS `width` + `position()` 兜底值同步）。
4. **列表**：去掉 `slice(0,5)` 上限 → 渲染全部；可见区**恰好 5 整行**（行高固定 `32px` + `box-sizing:border-box`，`max-height:178px` + 滚动）；运行中/失败置顶排序。
   - 踩坑：仅靠 CSS 估算行高不可靠（178px 实测露出 6 行），必须**固定行高**才能精确控制可见条数。

## 五、对抗式审查方法论（可复用）

1. **脚本比对「CSS 定义 vs JSX/querySelector/classList 用法」**：找「用了没定义」的孤儿类与「定义了没用」的死类，比肉眼 review 可靠。
2. 注意正则要覆盖 `className: "…"`、`el.className = "…"`、`querySelector(".x")`、`classList.*`、**`innerHTML` 模板字符串**（漏抓会把在用类误判成死类）。
3. 纯前缀替换安全性的原理：前缀替换同时作用于 CSS 与 JSX，天然保持一致；只需防「子串误伤」（用精确前缀 + 事后 grep 旧前缀残留）。

## 六、AI Coding 踩坑经验（文章素材，10+ 条）

1. **AI 改错模块的根因不是“文件没拆”，而是“命名不隔离 + 文档没钉边界”**——两个文件里类名共享照样串；拆文件不解决根本问题。
2. **类名前缀 = 模块身份证**：`模块 → 唯一前缀` 写进 AGENTS.md，AI 一 grep 就知道该改哪。
3. **AGENTS.md 必须随功能演进同步**：3 模块变 4 模块时还写旧的，等于把错误信息喂给下一个 AI。
4. **新增模块要有强制 SOP**（唯一前缀 + region + 注册 tab + 更新文档），把“约定”变“检查项”。
5. **对抗式审查用脚本比对 CSS/用法**，别肉眼 review 大文件。
6. **别迷信“拆文件 + 构建步骤”**：对 800+ 用户插件，单 bundle 无构建最稳；治理靠命名 + 文档，性能/兼容不受影响。
7. **死类也是污染**：JSX 挂无 CSS 的类名，AI 会误以为有用；审查顺手清。
8. **CSS 行高估算不可靠**：要精确控制可见条数（如“恰好 5 行”），必须**固定元素高度**（`height:32px;box-sizing:border-box`），不能靠算 `max-height`。
9. **innerHTML 全量重建会闪**：hover 背景闪烁的根因是 DOM 反复替换；用**内容记忆化**（HTML 字符串比对）避免。
10. **平台语义要摸清**：归档（`workspaces.archivedSessionIds`）、子代理（`origin:"subagent"`）会话不该出现在普通列表；要跟侧边栏行为对齐。
11. **发布链路的大坑**：
    - `pnpm link` 软链会被更新重建弄成**悬空相对路径** → 插件整个消失；且 `pnpm-lock.yaml` 里的 `specifier` 错值会让每次 relink 都重建错软链 → 要 `pnpm install` 从 package.json 对账；
    - `dsh.profile.bundles` 少了插件 → 插件根本没被组合 → 需要在 bundles 列表里；
    - npm 账号开了「发布需 2FA」→ 静态 token（无 bypass）和 `--otp` 都可能被拒，交互式 `npm login`+当场输码最稳，或生成 bypass-2FA token。
